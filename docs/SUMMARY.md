## 4. Defects found and fixed during verification

Recorded because finding these was the substantive part of the work, and
several would have been invisible without running the thing.

| Defect | Consequence had it shipped |
|---|---|
| `show_flash()` passed a bound method to `getattr()`, which wants an attribute *name* | every success/error message crashed the app |
| `_gate()` treated an empty role tuple as "no roles allowed" | dashboard hidden from every non-admin |
| `query_df()` never implemented the type coercion its docstring claimed | every `NUMERIC` column raised `ArrowTypeError` inside `st.dataframe` |
| `db.py` read only `os.getenv`, never `st.secrets` | first Cloud deploy failed: "DATABASE_URL is not set" while plainly set |
| `enroll_student()` inserted a second row on re-enrolment | violated `uq_enrollments_student_section` after a withdrawal |
| `trg_audit_grade_change` set `failed` on a cleared grade | withdrawal hit a CHECK violation |
| `insert_section()` passed the course code as the course name | every new section misnamed |
| `list_students()` doubly-qualified an alias (`a.u.first_name`) | the students screen failed to render |
| Sidebar radio used labels as options with an index `format_func` | navigation never matched |
| Seed attendance correlated status with `student_id` | two students at 100% absence in the report |
| `random()` through a `LATERAL` subquery was hoisted by the planner | all 212 attendance rows got one identical status |
| Streamlit served a stale module after a source edit | `hide_index` did not appear in screenshots |
| `show_flash` / `st.radio` / `AppTest` usage | three separate harness bugs in the screenshot and test tooling |

One incorrect claim of mine was also corrected in the documentation: I had
asserted that Streamlit Cloud's dual-stack egress would let the deployed app
reach an IPv6-only Supabase database. The deployment disproved it.

## 5. The one blocker

Supabase free-tier projects publish **IPv6-only** database hostnames.
`db.<ref>.supabase.co` has an AAAA record and no A record — confirmed against
Cloudflare, Google and Quad9, on two separate project refs.

`psycopg2`, `psql` and the Streamlit Cloud container all resolve addresses via
`getaddrinfo`, which returns nothing usable when the only record is AAAA and
the client has no IPv6:

```
could not translate host name "db.<ref>.supabase.co" to address:
No address associated with hostname
```

The IPv4 connection pooler is a paid-plan feature, so a free-tier Supabase
database has **no IPv4 route at all**. Only the SQL editor works, because it
runs inside Supabase's own network.

Resolution: use a provider with IPv4 on a free tier. The brief permits this
explicitly — *"Use any cloud based database that you want as Railway, Render,
Supabase, or others."*

| Option | Cost | Note |
|---|---|---|
| **Neon** | free, no card | recommended — standard `postgres://` DSN |
| Railway | trial credit, then card | acceptable |
| Render | free instance | **avoid** — the free instance expires |
| Supabase Pro | paid | works if you prefer to stay with Supabase |

**No code changes are required.** `src/db.py` speaks plain `psycopg2`, resolves
its DSN from a single `DATABASE_URL` setting, and the schema is standard
PostgreSQL 15+ with no Supabase-specific dependency: no ENUM extensions, no
Supabase Auth, no PostgREST, no RLS.

## 6. Next steps

### 6.1 Provision an IPv4 database — required

1. Sign up at **neon.tech**, create a project, keep the default Postgres.
2. Copy the connection string, which resembles:
   `postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`

### 6.2 Apply the schema — required

Neon → **SQL Editor** → paste `supabase/apply_all.sql` → **Run**.

`apply_all.sql` is the three migrations concatenated, so the schema applies in
a single paste with no local database connection. Already verified against a
clean PostgreSQL 17 instance: 144 statements, 13 tables, 8 functions, 6
triggers, 62 constraints, clean exit.

Expected on completion:

```
 users 33 · students 25 · instructors 6 · sections 18 · enrolments 57
 assignments 15 · submissions 62 · attendance 212
```

### 6.3 Point the app at it — required

Streamlit Cloud → your app → **Settings → Secrets**. Replace the whole file
contents with one line — no section header, since the lookup reads top-level
keys only:

```toml
DATABASE_URL = "postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require"
```

Save, wait ~1 minute, then **Rerun**. Sign in with `admin` / `Passw0rd!`.

### 6.4 Optional hardening

Run `supabase/hardening.sql` (or its Neon equivalent) to revoke the Data API
roles. Proven harmless by `scripts/verify_hardening.py`.

### 6.5 Outstanding on the author

- **Student numbers and names** — three placeholders in `docs/report.md` §1.4.
- **PL/pgSQL sign-off.** The brief asks for PL/SQL and names Supabase, which
  is PostgreSQL and has no PL/SQL. §2.5 of the report argues the equivalence;
  confirm it is acceptable before submitting. This is the only outstanding
  item that could affect marks independently of deployment.
- **Group members as collaborators** — add them under
  *Settings → Collaborators* so they can push.

### 6.6 How to read a failure

| Symptom | Meaning | Action |
|---|---|---|
| `DATABASE_URL is not set` | secret not saved, or nested under a `[section]` | re-enter as one top-level TOML line |
| `could not translate host name … to address` | IPv6-only database, or empty DNS | use a provider with IPv4 |
| `relation "…" does not exist` | schema not applied | run `apply_all.sql` |
